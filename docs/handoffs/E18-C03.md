## Changes and decisions
- **Frame inputs** (frame v2, all optional and additive):
  - roll `last_fallen`: the pin with the highest knockdown sequence that roll (0 if none). The frame's last fallen pin is that of the last roll that felled any, so an empty second roll keeps roll 1's. This is how "the last distinct pin to fall" is read: physical knockdown order, not rack position.
  - context `match_score` and `match_target`: the match before this frame; the lab passes target 0 in Practice, which has none.
- **Primitives** (design names → rule vocabulary):
  - `condition.first_roll_standing` → condition `leave_min: n` (the first roll left at least n standing).
  - `scaling.accurate_rolls` → `per: "accurate"` (rolls graded sweet or perfect; at most two, so Sweet Spot's +6 cap needs no extra rule).
  - `scaling.positions` → `per: "fallen_at:7,8,9,10"` (fallen pins at the listed distinct positions 1–10).
  - `condition.match_behind` → condition `behind: true` (score × 2 < target; never with target 0; exactly half is not behind).
  - `condition.last_fallen` → condition `last_fallen: "self"` (on a pin: it fell last) or `last_fallen: "<pin id>"` (the pin that fell last is that item).
  - Validation in FrameRules and the catalogue contract refuses out-of-range leaves, repeated or out-of-range positions, a suffix on `accurate`, `self` off a pin, an unknown pin, a non-boolean `behind`, a negative target and a roll `last_fallen` that did not fall.
- **Explanation:** results carry `facts` (leave, last fallen, accurate rolls, behind, match score and target), so the log shows the checked numbers: "first roll left 4, needs 4+", "behind: 100 vs half of 300", "Crown Pin fell last", "per sweet or perfect roll", "per back-row pin down". A Crown that fell but not last gets an explicit "+0 Value (did not fall last)" step, as its brief asks.
