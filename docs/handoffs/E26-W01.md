## What was built
- **Web preset** (export_presets.cfg, preset 1 "Web"):
  - Single-threaded (`variant/thread_support=false`), so the page needs no SharedArrayBuffer and no COOP/COEP headers, and any static web server can host it.
  - Desktop VRAM compression only.
  - Tests, docs, tools and build output are excluded.
  - A head include adds `touch-action:none` on the canvas and blocks overscroll, text selection and the iOS callout, so the page cannot scroll, zoom or select during a gesture.
- **Browser QA status** (src/platform/web_qa.gd):
  - Exists only in a Web build opened with `?qa=1`; added by bootstrap.gd, which is a three-line change.
  - Prints `ROGUEWOOD_WEB {json}`: screen, lab state, history, score, cancels, the ball and button positions in window pixels, whether a saved attempt exists, and fps.
  - Also logs pointer input as the game receives it (`ROGUEWOOD_WEB_INPUT`).
  - It only reads; it never drives the game.
- **JW01** (tests/web/web_journey.mjs, run by `python3 tools/qa.py web`) exports the build, serves it locally and drives headless Chromium through Playwright:
  - A fresh menu.
  - The canvas computes `touch-action: none`.
  - The first tap leaves audio running.
  - Enter the League, then throw with a real mouse drag on the ball (touch emulation).
  - The roll settles and the attempt is saved.
  - Reload the page: the menu offers Continue from IndexedDB; Continue resumes with the committed roll.
  - No script errors.
  - It records the build sizes, load time and the frame rate while rolling. `--inject-failure` exits 1.
- **CI:**
  - The install step also copies `web_nothreads_release.zip`.
  - The `game` shard runs `qa.py web` after installing Playwright 1.63.0 and Chromium.
  - Artifacts go to `artifacts/e26-w01/`.
- **Build for self-hosting:** the owner hosts the game themselves (2026-11-04; the GitHub Pages workflow was dropped). Every CI run's `game` shard uploads the exported folder as the artifact `web-build` (kept 30 days); `python3 tools/qa.py web` also leaves it in build/web/ locally.

## Findings
| Area | Result |
|---|---|
| Jolt physics in the browser | Works single-threaded. The lane, pins and a strike play in Chromium. Web results are not yet compared with the native physics digest; ADR 002 allows a web-specific baseline. |
| Saves | `user://` lives in IndexedDB. The committed throw survives a page reload, and Continue resumes it (J07's write and backup code is unchanged). |
| Audio | Godot resumes its AudioContext on input. Headless Chromium does not enforce the autoplay block, so JW01 can only assert "running after the first tap". Real-browser behaviour still needs a check on a device. |
| Touch | The canvas blocks scrolling and zooming. Mouse input goes through touch emulation. Real touch on a phone is untested. |
| Load | The menu appears after about 2.5 s from a local server. |
| Size | The download is about 94 MB uncompressed (wasm 38 MB, pck 60 MB); with gzip, the wasm is about 9 MB and the pck still about 57 MB. The pck is mostly item, rival and Clubhouse art as imported textures. This is too big for mobile data and is E26-W02's first task: lossy or VRAM-compressed web textures, plus trimming unused imports. |
| Frame rate | About 13–17 fps in headless Chromium with SwiftShader software rendering. That says nothing about devices; a real-phone figure needs the self-hosted build on a phone. |
| **Gesture timing (for E05-R1a)** | The gesture uses the frame clock, so at low frame rates a flick's samples are a frame or more apart. A mouse-up that lands a frame after the last move then reads as a "short" cancel. JW01 sends the last move and the release in one browser task, like a real lift-off. **R1a should take sample times from input events, not frames**, so low-fps devices don't lose throws. |

## Owner action
- **Hosting the build:** download the `web-build` artifact from a CI run (Actions → the run → Artifacts), unzip it, and serve the folder from any static web server, with `index.html` as the page.
  - **Required:** serve `.wasm` as `application/wasm`; most servers already do.
  - **Not needed:** COOP/COEP headers (the build is single-threaded).
  - **Recommended:** gzip or Brotli compression (the wasm shrinks from 38 MB to about 9 MB), and HTTPS, which phones need for an installable app later (E26-W02) and some browsers need for persistent storage.
  - **Saves:** live in the visitor's browser (IndexedDB) for that host and path. Moving the game to a new address starts with empty saves.
