# PACK-1 — League asset packs: evaluation and proposal (owner review, 2026-11-24)

## Context
The owner asked whether assets could be split by League, so the Web game downloads a League's art only when a run in that League starts, behind a load screen after "New Run". The goal is a smaller download. This is an evaluation and a plan; nothing is built yet.

## Verdict
**Viable, and worth doing. But it is not the biggest lever today, and it should come second.**

| | Download now | Saved |
|---|---|---|
| The whole Web game (`index.pck` 124.7 MB + engine `index.wasm` 38.0 MB) | ~163 MB | |
| A. Lossy image compression, every League | ~88 MB | **~75 MB** |
| B. Neon in its own pack (today) | ~148 MB | ~15 MB |
| A + B (today) | ~78 MB | ~85 MB |
| A + B with six Leagues (each adding ~15 MB of its own art before A, ~5 MB after) | base stays ~80 MB; each League ~5 MB on first play | grows with every League |

How these were measured (2026-11-24; build of 01:58, before the Neon celebrations, which are code):
- **Images are 100.6 MB of the pack:** 107 sheets, all imported lossless at full size (`compress/mode=0`, `size_limit=0`). Re-encoding a ten-sheet sample (rivals, items, environment, ribbons) as lossy WebP at quality 90 came to **25%** of the lossless size; at quality 80, 19%.
- **What is truly Neon-only is smaller than the folders suggest, about 15 MB:**
  - Neon's environment and backdrops (`assets/leagues/neon`, 4.9 MB);
  - its four rival sheets (~7.6 MB);
  - its music (~2.9 MB).
- **Neon's 28 items are shared:**
  - Most unlock by beating Neon's bosses and are then sold in every League's shop; `ball_mod.bumper_guard` is available from the start.
  - They appear in the Clubhouse collection too.
  - So their art (`assets/items/neon`, 9.5 MB) must stay in the base download, as must every League's Clubhouse plaques and trophy (Neon's are 3.6 MB).
- **The Web build holds the whole pack in memory.** The iPhone tab restart for memory (PERF-2) is partly this, so both A and B also cut the phone's memory use.
- **E26-W01 already planned A:** its handoff says shrinking the download is "E26-W02's first task: lossy or VRAM-compressed web textures, plus trimming unused imports". It has not happened, and the pack has grown from 60 MB to 125 MB since.

**Recommendation:**
1. **Do A first.** It cuts the download by about half for everyone, with no new loading code. It is a visual trade-off that you review before it ships.
2. **Then do B.** It is a sound design for the long run: six Leagues, UI-A8's large per-Division backdrops, and faster updates when only one League's art changes. Build it behind a short proof-of-concept gate, because downloading and mounting a pack at runtime on Godot Web is not well trodden.

## Phase A — compress the Web build's art (PACK-A; small-medium)
- **Owner and lane:** an import-setting change on every image. That is the asset audit, Codex's lane; Claude can take it if you reassign it, as with UI-A9-N.
- **Change:**
  - Painted sheets import as lossy WebP (`compress/mode=1`, `compress/lossy_quality` about 0.9).
  - Pixel-crisp UI (icons, frames, fonts, small UI PNGs) stays lossless. A list in `tools/` decides which is which, so the choice is reviewable and repeatable.
- **Trim unused imports:** exclude art the game never loads.
  - **Likely candidates:** `assets/clubhouse/sources/*` (no references found) and one of each duplicated ribbon pair (`ribbon.<x>` beside `ribbon.mastery.<x>`).
  - **Runtime audit:** the Clubhouse builds its file names (`clubhouse_model.gd` `asset_id`), so a text search is not proof. A run of every journey logs each texture loaded, and only art never loaded is excluded.
  - **Keep:** `assets/items/sources` (the item cards draw from it), `assets/leagues/*/source.environment.png` (the lane environments), and `assets/art_direction/card-art.png` (the runtime fallback, PERF-4).
- **Review gate:** before and after captures at phone size for:
  - rival portraits, the shop's item cards, the card inspector at full size;
  - the League environments, Clubhouse ribbons and plaques.
  - You approve the look before merge.
- **Budget:** `qa.py web` records `sizes.json` but enforces nothing. Add a download budget (for example, `index.pck` at or under 60 MB, adjusted when you decide); JW01 fails above it.
- **Files:** `assets/**/*.png.import` (generated by a tool, not by hand), `export_presets.cfg` (Web exclude filter), `tools/qa.py` (budget), `tests/web/web_journey.mjs` (budget check), a new `tools/web_textures.py`.
- **Checks:**
  - `qa.py web` (JW01) with the new size;
  - J02 rendered (ball looks), J05 (shop cards), J11 (Clubhouse) and J22L01/J22L02 rendered;
  - the art journeys in CI's art shard;
  - Graphics Low still works (its 512 px copies come from the lossy originals).

## Phase B — League packs fetched at "New Run" (PACK-B; large)

### B0. Proof of concept (gate; about a day)
- **The flow to prove:** a throwaway Web build that downloads a small pack with `HTTPRequest` into `user://packs/`, mounts it with `ProjectSettings.load_resource_pack`, and shows one texture from it. It must:
  - work on the iPhone Home Screen app and desktop Chrome and Safari;
  - survive a reload (cached in IndexedDB; `OS.is_userfs_persistent()`);
  - work with a texture referenced by UID from a scene in the base pack.
- **Why the gate:** forum reports describe this flow on Web as fragile, and how a pack's UID cache merges with the base's is undocumented.
- **If it fails:** stop and keep A only, or use a fallback: the packs as separate files fetched by the page (JavaScriptBridge `fetch`) and written to `user://`, then mounted.

### B1. What goes in a League's pack
- **Rule:** only media used only in that League's runs. Neon's would hold:
  - the environment and Division backdrops (`assets/leagues/neon/**` images, and UI-A8's later);
  - its rival sheets (`assets/rivals/{slick,laser_lena,dj_flicker,dj_flicker_champion}.png`);
  - its music (`assets/audio/music/neon.ogg`);
  - its celebration stings (`assets/ui/alley_screen/neon/*.wav`).
- **Always in the base download:**
  - every script (packs never carry code, so class names and preloads keep working);
  - items (shared shops), the Clubhouse (plaques and trophies for every League), the title, the House League (the tutorial and first run), the League Board's preview text;
  - every League's content JSON (the board and the "Continue Run" check read it without art).
- **Manifest:** each League's `assets/leagues/<id>/manifest.json` gains a `pack` list (paths or globs), so the pack's contents are declared beside the theme.
- **Coupling today is clean:**
  - No base script preloads Neon's rival sheets, environment, music or items (a search of `src/` and `assets/`).
  - Music is looked up by path when played (`src/presentation/soundtrack.gd`).
  - Rival portraits load on demand (`src/presentation/rival_art.gd`).
  - Neon's code (`assets/leagues/neon/rule_overlay.gd`, the celebration kit) is preloaded by base scripts, which is why scripts stay in the base.

### B2. Build and deploy
- **Export:**
  - The Web preset's exclude filter drops every pack path.
  - One pack preset per League (`export_filter="resources"` from the manifest's list) exports `build/web/packs/<league>.<hash>.pck`.
  - A `packs.json` in the base (id, file, size, sha256) tells the game what to fetch.
  - A tool (`tools/web_packs.py`) writes the presets' filters from the manifests, so they never drift.
- **Native builds keep one pack.** Packs apply only to the Web export, so desktop and phone builds and every headless and rendered journey are unaffected.
- **Deploy:** `.github/workflows/web-preview.yml` exports the base and the packs, and deploys both to Pages. File names carry a content hash, so the browser's cache and `user://` never serve a stale pack.
- **Updates:** a release that changes only code re-downloads the base, not the League packs.

### B3. The load screen after "New Run"
- **Where:** in `src/bootstrap/bootstrap.gd`, `_start_session()` and `_continue_attempt()` both call a new `_ensure_league(league_id)` before `_begin_attempt()`. It is a new `src/platform/league_packs.gd`:
  - Not on Web, or the pack already mounted: continue at once.
  - Cached in `user://packs/` with the right hash: mount it (a brief flash of the screen at most), then continue.
  - Otherwise, a full-screen "Getting <League> ready" screen in the League's colours.
    - It shows the ball-and-pin lane from the web loader (`rw-loader`), drawn in Godot, with real progress (bytes over `packs.json` size), and a Cancel that returns to the Clubhouse.
    - On a network failure: "Couldn't fetch the <League>. Check your connection." with Try Again and Back.
  - Before mounting, a sha256 check against `packs.json`. Old versions are deleted.
- **Optional:** prefetch in the background while the player sits on the League Board with a League selected, so New Run is often instant. Recommended, behind the same code.
- **Settings:** a "Downloaded Leagues" line under Graphics (size used, Remove) for storage-tight phones. Optional; later.

### B4. Guarding the split
- **A `content` check (tools/qa.py, run_tests):**
  - Every path in a pack list exists.
  - No file outside a League's own code `preload`s a pack path. A preload would pull the asset into the base, or fail before the pack is mounted.
  - Nothing in the base's always-loaded set (title, Clubhouse, board, House) references a pack path.
- **A new browser journey, JW02** (`tests/web/`, like JW01): boot (the Neon pack not fetched), choose Neon, New Run, the load screen with progress, the run plays with Neon art, reload and Continue (no download the second time, from `user://`), and a forced network failure showing Try Again.

### B5. Known risks
- **UID references across packs:** proven or disproven in B0. The mitigation is path references for pack assets (the base resolves them after mounting).
- **iOS storage:**
  - IndexedDB can be evicted; the screen simply downloads again.
  - Private browsing cannot persist; it downloads each session.
- **Memory:** a mounted pack is held in memory for the session. Unmounting is not supported, so play only fetches the League in use.
- **Work for every new League:** each needs its pack list. This is a manifest field plus the content check, and it is part of the League template (docs/ROADMAP.md, "League template").
